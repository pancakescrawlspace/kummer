# Kummer surface: p-adic density of rational points

$p$-adic density of rational points on the Kummer surface $X : y^2 = f(x)f(t)$,
where $f = x^3 + Ax + B$ has no repeated root and $X = \mathrm{Kum}(E \times E)$
for $E : v^2 = f(u)$.

Tested with PARI/GP 2.18. Run everything **from this directory** (the scripts
`read()` each other by relative path), and always close stdin, otherwise `gp`
drops into its interactive prompt after the script:

```sh
gp -q -s 4000000000 driver.gp < /dev/null
```

Note: do **not** put `default(parisize, N)` inside a script — in `gp` that
aborts the rest of the file. Use the `-s` flag as above.

## Files

| file | contents |
|---|---|
| `kummer2.gp` | **core.** `densegroup(Em, pts, p)` — is the subgroup generated by `pts` dense in `Em(Q_p)`? Also `Mval`, `sqclass`, `twistdata`. Odd `p`. |
| `driver.gp` | the search. `sweep` + `procyclic` + `hybrid` are the fast path (see **Search strategy** below); `build`/`report` are the slow pure-descent reference path, `hunt(A,B,p,target,DMAX)` a targeted single-class search. |
| `p2.gp` | the `p = 2` variant: `densegroup2`, `M2val`, `sqclass2` (8 classes), `report2`. |
| `cover2.gp` | independent verification for odd `p`: `coverage(A,B,p,k,ds,NB)` checks that every genuine reduction mod `p^k` of a point of `X(Z_p)` with `y` a unit is hit by an honest rational point. |
| `control.gp` | the control experiment for the `p = 3` open case (document §5.2.2): `armA`, `find3`, `armB`. |
| `cm-torsion.gp` | the CM mechanism at `p = 3` for `f = x^3-2` (document §5.2.1): `torsionQ3`, `row`, `correlate`, `structure`. |
| `cover-p2.gp` | the same check at `p = 2`, with exact rational arithmetic and the corrected target set (see below). |
| `kummer.gp` | the earlier single-generator version (`densecyclic`, `scan`) over the `t_0`-family. Kept only as the reference implementation for `validate.gp`. |
| `validate.gp` | validates the `p`-adic density test against an exact-rational reference implementation, and `densegroup` against `densecyclic`. |

## Reproducing the results

Main result, `f = x^3 + x + 1`, all odd primes up to 200 — one pass, ~5 s:

```
read("driver.gp");
SW = sweep(1, 1, 1500, 50);          /* 92k twists, each with a free point */
hybrid(1, 1, SW, 200, 60, 20000);    /* 45 / 45 primes */
```

The slow reference path, kept for cross-checking, is

```
D = build(1, 1, 3000);               /* ~11 s: ellrank on every twist */
report(1, 1, D, 200);                /* 43 / 45; 131 and 149 then need hunt() */
```

`p = 2` (all eight square classes):

```
read("p2.gp");
report2(1, 1, 400);
```

Independent coverage check on the surface:

```
read("cover2.gp");
coverage(1, 1, 5, 3, [1, 3, 5, -35], 400);      /* complete mod 5^3 */
read("cover-p2.gp");
cov2(1, 1, 4, [1,-1,3,5,6,-6,30,-30], 90);      /* complete mod 2^4 */
```

The CM case discussed in §5.2 of the document:

```
read("driver.gp");
SW2 = sweep(0, -2, 1500, 50);
hybrid(0, -2, SW2, 100, 60, 15000);   /* every odd 5 <= p <= 97; p=3 is 3/4 */
hunt(0, -2, 3, 3, 12000);             /* class [u*3] at p=3: no witness found */
```

Why that class and no other (§5.2.1) — the extra `Q_3`-rational 3-torsion point
`T_d = (2d, sqrt(6d^3))` exists exactly when `d` is in the class `[u*3]`:

```
read("cm-torsion.gp");
correlate(1500);      /* 458 twists, 0 mismatches with the prediction */
structure(-3);        /* (Z/3)^2, read off from Q_3-points  */
structure(3);         /* cyclic Z/3                          */
```

The control experiment (§5.2.2) — is the failure local, or about the curve?

```
read("control.gp");
armA(0,-2,7,1,400);        /* p=7, same CM curve, (Z/3)^2 : 20 of 25 dense  */
find3(21,26);              /* which classes have M=9 at p=3                 */
armB(21,26,2,3000);        /* non-CM, E[3] decomposable : 0 of 36 dense     */
armB(-24,26,2,3000);       /* non-CM, E[3] decomposable : 15 of 43 dense    */
```

Sanity checks:

```
gp -q validate.gp < /dev/null
```

## Two things to be aware of

**A fixed bug.** An earlier `densegroup` short-circuited with
`if(rem == 1, break())` once the running index reached `M`. That skipped the
remaining generators, so they never contributed to the kernel lattice `L` — and
condition (ii) is tested only on a basis of `L`. A twist with generators
`P_1 not in E_1` and `P_2 in E_1 \ E_2` (which *is* dense) was reported as not
dense. The bug is one-sided: it can only turn a true "dense" into a reported
"not dense", never the reverse, so no positive result was ever affected. It is
fixed here (`rem == 1` gives `divisors(1) = [1]`, which the generic branch
handles correctly).

**The target set at `p = 2`.** For odd `p`, if `y` is a unit and
`y^2 = s mod p^k` then `±sqrt(s) = y mod p^k`, so "all congruence solutions" is
the right target set. At `p = 2` that congruence has *four* solutions but only
two are genuine reductions, so the naive target set is a factor 2 too large and
the check reports a spurious failure. `cover-p2.gp` uses the corrected
enumeration: lift `x, t` mod `2^(k+4)`, require `s = 1 mod 8`, record
`±sqrt(s)`.

## Search strategy

There are two ways to get rational points on the twists, and they have very
different costs.

**The `t_0` sweep.** A twist `E_d` has an affine rational point iff `d` is the
squarefree part of `f(t_0)` for some `t_0`, and then `(t_0, 1)` *is* such a
point. So sweeping `t_0 = a/b` and bucketing by squarefree part hands out one
generator per twist for free, and the family is complete — no twist with a
rational point is missed.

**Per-twist descent.** `ellrank` on each `E_d` in turn. This finds generators
of any rank, but you pay for a 2-descent every time.

Measured on `f = x^3 + x + 1`:

| strategy | throughput | rank-2 twists produced |
|---|---|---|
| `t_0` sweep | 91963 twists in 663 ms = **0.007 ms/twist** | 54 of 91963 (0.06%) |
| per-twist `ellrank` | 366 twists in 833 ms = **2.28 ms/twist** | all, on demand |

The sweep is ~300x cheaper per twist but almost never yields **two independent
points on one twist**: that needs a collision of squarefree parts, and
`|a|,b <= H` gives ~`H^2` values of `f(t_0)` spread over a range ~`H^4`, so
collisions stay negligible (7.5k sweep -> 18, 92k sweep -> 54). Rank 1 is
insufficient exactly when `E_delta(Qp)/E_1` is not cyclic.

**The triage.** That condition depends only on `(p, delta)`, not on which twist
in the class you take, since all `d` in one class give `Qp`-isomorphic curves.
So one local computation per `(p, delta)` — four per prime, no point search —
decides the path. `procyclic()` implements it (exact at good reduction via
`ellgroup`; conservative at additive primes, so the cheap set is never
overstated).

| `f` | `(p,delta)` pairs | procyclic, cheap path | rank >= 2 mandatory |
|---|---|---|---|
| `x^3+x+1`, `p < 200` | 180 | 158 (88%) | 22, at `p = 31,47,67,131,139,149,173` |
| `x^3-2`, `p < 100`   | 96  | 78 (81%)  | 18, at `p = 3,7,13,19,31,37,43,61,67,73,79,97` |

That second list is exactly `{3}` together with `p = 1 mod 3`. No prime
`2 mod 3` appears. This is why a rank-1-only search on the CM curve looks like
it "fails for `p = 1 mod 3`": CM by `Z[zeta_3]` is what makes those classes
non-procyclic. It is a blind spot of the method, not a fact about the surface —
see §5.2 of the document.

**Result.** `hybrid()` settles all 45 odd primes below 200 in one pass in ~5 s,
including `p = 131, 149`, which the pure-descent path only reached via separate
targeted `hunt()` calls. Of the 180 pairs, 134 are resolved straight from the
sweep with no descent at all.
