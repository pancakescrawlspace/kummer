plusminus-cube.gp, check 4 only -- the long deep scan at p = 2
======================================================================

A single run of check 4 for each of a = 3, 5, 7, launched in parallel as

    echo 'AONLY=<a>; BUDGET=5400; read("plusminus-cube.gp")' | gp -q -s 8000000000

on 2026-09-01.  The default budget in the script is 300 s per value of a and
produces results/plusminus-cube.txt; this file records the deeper run.

Two things to know when reading it.

  * The budget is a FLOOR, not a deadline.  check 4 tests the clock only
    between values of |d|, and a single twist can spend an hour inside
    ellheegner / ellsaturation, so each process ran to roughly 8000 s against
    a 5400 s budget.  The "reached |d| <= N" line is the honest bound.

  * The progress lines below are in the format the script had WHEN THIS RUN
    STARTED.  The script was edited while the run was in flight -- the current
    version prints the witness table on every progress line, not just a count.
    The numbers are unaffected: gp had already parsed check 4 into memory
    before the edit, so the computation is the pre-edit code throughout.  The
    edit did corrupt what gp read AFTER the driver returned, and that trailing
    output has been removed here.
